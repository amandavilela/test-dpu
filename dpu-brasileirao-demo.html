    What's real here vs. simulated

    The free football-data.org tier returns all 5 fixtures in a single JSON response, this page deliberately drips each fixture into its ticket at a staggered interval using DPU's new JS insertion methods (streamHTML / appendHTML) where the browser supports them, falling back to a small manual polyfill otherwise, so you can see what the insertion pattern looks like once a real backend does stream fragments as they resolve. The declarative half of the proposal <?start>/<?end> processing instructions plus a <template for>, needs the *initial* HTTP response itself to be streamed out of order, which a static page like this one can't produce on its own. Here's the shape of it: 

    <div id="match-3"><?start name="match-3"><?end></div>
...
<template for="match-3">
  <div class="ticket">...</div>
</template>

    To test native execution, enable chrome://flags/#enable-experimental-web-platform-features in Chrome 148+.
