    What's real here vs. simulated

    The free football-data.org tier returns all 5 fixtures in a single JSON response, so this page deliberately shuffles their arrival order and drips each one in at a staggered interval, to stand in for fragments landing out of order from a real backend. Each ticket is rendered up front with a marker pair, <?start name="match-3"><?end>, wrapping fallback skeleton content; each fixture then arrives as a <template for="match-3"> that patches into its marker whenever it shows up, regardless of arrival order. The whole thing is written through a single sanitized element.streamHTML() call, no JavaScript fallback, the browser itself resolves the out-of-order patches. Here's the shape of it: 

    <li id="match-3"><?start name="match-3">...skeleton...<?end></li>
...
<template for="match-3">
  <div class="ticket">...</div>
</template>

    This still can't make the initial page navigation itself stream out of order, that would need a server that chunks the first HTTP response, which this static page doesn't have. Without native support the fixtures below just stay as placeholders, enable chrome://flags/#enable-experimental-web-platform-features in Chrome 148+ to see them resolve.
